# Clear Tool 2.4.2 — Guided tools, device health & reliable downloads

All improvements since 2.3.0 in one public release, including the previously local 2.4.0 and 2.4.1 work.

## A simpler way to use your tools

- A redesigned home and toolkit with clear tasks, quick access to PC checks, space cleanup, battery reports and app updates.
- Search, categories and favorites across 14 tools/workspaces, with advanced diagnostics grouped separately.
- Six native utilities: SHA-256 file comparison, battery HTML reports, current battery charge, physical drive status, sleep diagnostics and stopped automatic-service review.
- Each native tool explains when to use it, what it returns and three simple steps before you run it. Results use readable summaries, with original evidence and JSON export available on demand.
- Progress, elapsed time, errors and the last utility result survive navigation during the session. Arabic/English, light/dark and keyboard focus are supported.

![A tool guide before running](https://raw.githubusercontent.com/Ahmed-Khalil-Mohamed/clear-tool/v2.4.2/docs/images/tool-guide-242-en.png)

## Device health and reviewed repairs

- Eight staged, read-only checks cover storage, memory pressure, Windows protection/restart state, device errors, startup entries, legacy game libraries, network adapters and recent System events.
- Inspect evidence, filter findings and export the latest report. The report retains its original scan time across restarts.
- Missing or inaccessible evidence remains unavailable. Reviewed SFC, DISM and DNS maintenance routes remain separate from the scan; no automatic repair is claimed.

## Downloads and updates you can verify

- A dedicated download workspace for PowerToys, Lively Wallpaper, Rainmeter, Windhawk, Flow Launcher and Twinkle Tray, using fixed WinGet package IDs.
- Review package identity and version before installation or upgrade. The app checks the installed identity and version afterward, distinguishing verified success, unverified completion, failure and cancellation.
- Keep the latest 30 operations locally, recheck installed versions and export operation details. Interrupted work is marked interrupted, not silently retried.
- Improved decimal-comma download parsing, restarted-transfer estimates, update previews and redundant-install checks. Driver availability still comes from Windows Update, and driver installation continues in Windows.

![Downloads and verification in English](https://raw.githubusercontent.com/Ahmed-Khalil-Mohamed/clear-tool/v2.4.2/docs/images/downloads-242-en.png)

## Performance and reliability

- Open from a validated saved inventory, then refresh live data with a visible timestamp and retry state. Expired, invalid or different-computer/account snapshots are rejected.
- Discover games and driver updates on demand. Pause network monitoring when unused and CPU/RAM sampling when hidden.
- Throttle file-scan events, exclude changing duplicate candidates, and preserve the exact displayed result during export.
- In earlier local measurements, reopening from a matching snapshot took 3.8–4.6 seconds versus about 20 seconds for a fresh scan. These are single-device observations, not a universal benchmark or FPS claim.

## Updating

Quit the old version from its system-tray menu, then run **Clear-Tool-Setup-2.4.2.exe**. Portable users should place the new executable beside their existing **ClearTool-Data** folder and retain that folder. Back up settings before upgrading. Clear Tool has no automatic self-updater.

Use **SHA256SUMS.txt** to verify the installer and portable file. GitHub's source archives are for building from source; they are not installers.

## Verification and scope

**65 automated tests pass.** Native checks exercised all six utilities, all eight health probes, navigation/report retention, checksum comparison and export. Guided layouts were checked in Arabic and English, both themes, at 760, 1024 and 1440 pixels. The actual 2.4.2 portable was checked for extraction, startup, catalog availability and a native drive-status operation without observed renderer errors.

Windows 10/11 x64 is the target; physical validation was on Windows 11 x64. WinGet/App Installer is required for managed app downloads and updates. Real repair commands, user-file deletion, network restrictions and third-party installation were not executed during UI validation; guarded paths have automated coverage. The installer was built, not installed during validation. Binaries are not signed with a commercial publisher certificate. Verify the source and checksums without disabling Windows protections.
